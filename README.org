vocaBull 2 (vb2)* is a flashcard web app for vocabulary building — a modern remake of the original [[https://github.com/achiwa912/vbs][vocaBull (vbs)]].  It blends the frequency-based *Shifting Learning Window (SLW)* method with time-based *Spaced Repetition (SRS)* techniques, while deliberately avoiding the "due debt hell" that demotivates users of strict SRS apps.

* Overview

The original vbs was built with Flask + Jinja2, which required a full server-side HTML render for every flashcard.  On a free PythonAnywhere plan this made card transitions painfully slow.

vb2 moves all interaction practice logic to the browser (Vue + JavaScript) and only talks to the Python backend on initial load and on explicit "sync with server" actions.  The result is a snappy, mobile-friendly flashcard experience.

- Status: *alpha*

* Features

** Flashcard review
- Word → meaning, and meaning → word practice modes
- Instant client-side card transitions (no server round-trip per card)

** Hybrid learning method
- *Shifting Learning Window (SLW)* — frequency-based repetition for words you are actively learning
- *Lenient SRS* — time-based scheduling for words you have marked as memorized
  - *No "due debt"* — skipping days or weeks does not flood you with overdue reviews

** Progress & persistence
- Words and progress are stored in a database (sqlite3 w/ WAL mode)
- Explicit (as well as automatic) /sync with server/ action to reconcile local and remote state
- Export and import all words and progress to a local file

** Mobile-friendly UI
- Optimized for both phone-sized and PC screens
  - swipe actions on mobile
  - keyboard shortcuts on PC

** Learn with voice
vb2 will pronounce words, definitions and sample sentences for you with browser's [[https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis][SpeechSynthesis]] capabilities.  Autoplay-mode will reduce clicking/tapping speak buttons.

** Bulk CSV import
You can import many words defined in a CSV file.  Can choose =,= (comma), =;= (semi-colon) or =\t= (tab) as delimiters.

** Auth
- JWT-based sessions
- Google OAuth sign-in
  - All you need is a gmail account.  Once signed in, a user account is automatically created in the database.

* Getting Started
** Prerequisites
- Python 3.13
- [[https://docs.astral.sh/uv/][uv]]
- [[https://nodejs.org][Node.js]] + [[https://pnpm.io][pnpm]]

** Installation
#+begin_src bash
git clone https://github.com/achiwa912/vb2.git
cd vb2

# Backend dependencies
uv sync

# Frontend dependencies
cd fe && pnpm install && cd ..
#+end_src

** Running Locally

In development the frontend is served by Vite and the backend by Flask.

#+begin_src bash
# Terminal 1 — backend
uv run python -m be.api  # to create initial database
flask --app be.api:app run --port 8000 --debug

# Terminal 2 — frontend dev server (Vite, default http://localhost:5173)
cd fe && pnpm dev
#+end_src

To run in "production-like" mode where Flask serves the built frontend:
#+begin_src bash
cd fe && pnpm build && cd ..
SERVE_FRONTEND=1 uv run python be/api.py
#+end_src

* Configuration
Create a =.env= file at the project root:

#+begin_src bash
export SERVE_FRONTEND=1
export CORS_ORIGINS=http://localhost:5173,https://achiwa912.pythonanywhere.com
export JWT_SECRET_KEY=<your-secret>
export GGL_CLIENT_ID=<your-google-oauth-client-id>
#+end_src

| Variable          | Purpose                                                     |
|-------------------+-------------------------------------------------------------|
| =SERVE_FRONTEND=  | When set to =1=, Flask serves =fe/dist= as static files     |
| =CORS_ORIGINS=    | Comma-separated list of allowed origins                     |
| =JWT_SECRET_KEY=  | Secret used to sign JWTs                                    |
| =GGL_CLIENT_ID=   | Google OAuth client ID                                      |

If you use Google OAuth, add your deployment URL under
*Google Cloud Console → APIs & Services → Credentials*.

* Deployment (PythonAnywhere)
Being able to deploy on PythonAnywhere is one of the goals, and because of this, I chose Flask over FastAPI for vb2.

A short summary — see the [[https://blog.achiwa.co.uk/posts/deployvb2pa/][project blog post]] for the full record.

1. Use the =innit= system image and Python 3.13.
2. Create a virtualenv and clone the repo:

   #+begin_src bash
   cd ~/
   mkvirtualenv vb2-venv
   git clone https://github.com/achiwa912/vb2.git
   #+end_src

3. Install backend deps into the PA virtualenv:

   #+begin_src bash
   UV_PROJECT_ENVIRONMENT=/home/achiwa912/.virtualenvs/vb2-venv \
     uv sync --no-install-project --python 3.13
   #+end_src

4. Build the frontend (=cd fe && pnpm build=) and commit =fe/dist=.
5. Create a new *manual-configuration* web app in the PA Web tab:
   - Source / Working directory: =/home/<your_account>/vb2=
   - Virtualenv: =/home/<your_account>/.virtualenvs/vb2-venv=
6. Point the WSGI file at =be.api:app=, load =.env=, and reload the app.

* Learning Method

vb2 combines two approaches:

- *Shifting Learning Window (SLW)* — a small high-frequency window (5 words) that repeats until you mark a word, then moves it to a waiting window to show up later (10 or more words), then to 'review'.  This is optimized for *frequency*.
- *Spaced Repetition (SRS)* — once a word is in the 'review' state, it reappears on a time-based schedule (1 day, 2 days, 4 days, …).  This is optimized for the *forgetting curve*.

Crucially, vb2 uses *relative day counters* rather than absolute due dates, so taking a break does not create a backlog.  Work daily and it behaves like SRS; skip a month and there is no "due debt hell."  That is, practicing the next day or 30 days later would be the same.

The goal: a kinder, more lenient alternative to strict SRS apps.
